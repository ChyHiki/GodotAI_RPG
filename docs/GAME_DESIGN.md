# FirstGame 设计文档

第三人称 3D 动作游戏（方向草案，随开发迭代更新）。

## 核心愿景

- 主打**近战手感**：攻击/闪避/受击的帧级反馈优先，再谈内容量
- 设计参考：黑魂（节奏与弹反/闪避）、鬼泣（连段爽感）、战神（镜头表现）
- 美术路线：M1 原语占位 → M2 起 Blender 低多边形风格（E:\blender\blender.exe）

## M1 垂直切片（已完成，待试玩反馈）

范围：移动 + 追尾镜头 + **前冲/后撤闪避(无敌帧 + 完美闪避)** + 单段攻击 + **格挡(减伤/完美格挡)** + **失衡条与处决** + 1 个敌人 + 竞技场 + 血条/失衡条/死亡重生。
验证目标：**移动镜头手感、攻击命中感、闪避躲攻击的可行性、"完美闪避"的回报是否够爽、格挡的攻防博弈、"弹反攒失衡 → 处决"的正循环**。

> M2 追加（2026-09-21，见下方"三段连击"一节）：攻击由**单段升级为三段连击**
> （`Slash` / `Slash2` / `Slash3` 三段专属动画 + 后摇取消 + 输入缓冲），
> 并补齐**顿帧 hitstop / 命中镜头震动 / 挥砍与命中音效**这三样命中反馈。

### 闪避与完美闪避（已实现，设计定稿）

设计目标：给"我不接这一下"一个**跟格挡平级的正当解法**，并让"卡着敌人挥击的那一瞬间闪出去"这件事
被明确奖励 —— 格挡奖励的是**勇气**（迎上去），闪避奖励的是**时机**（擦着边过去）。

| 决策项 | 结论 | 理由 |
|---|---|---|
| 机制形态 | **前冲 / 后撤两种**，各带独立位移，全程无敌帧 | 闪避的价值在"位移 + 无敌"同时给：只有无敌帧就成了原地站桩，只有位移就成了加速跑 |
| 按键 | **Shift**（占用了原翻滚键位） | 大拇指可达、不与左键攻击 / 右键格挡抢手；沿用旧键位，肌肉记忆不用重建 |
| ★ 翻滚被**取消** | 旧的 `ROLL / RollLeap` 整体停用，键位与状态一起让给闪避 | 翻滚的观感承诺是"无敌 + 位移最长"，它和闪避做的是**同一件事**（位移型无敌）。两者并存时玩家只会按更强的那一个，另一个必然被架空。**只留一套位移无敌**，强度也只需要调一处 |
| ★★ **方向规则** | **任意方向键 + Shift = 前闪**（身体**先转向**按键指向的方向、再顺它冲出去）；**单按 Shift = 后闪**（朝身体正后方跳开、**不改朝向**） | 第一版写成"有 W 才前冲、其余一律后撤"，于是 A/S/D+Shift 全部变成后撤 —— 想往左拉开**必须先转镜头**或先走两步把身体转过去，闪避最核心的诉求（"我要去那边"）被规则吃掉了。改成"有输入 = 我去那个方向"后，按键意图与画面结果终于一一对应。**前闪还额外转身**：不转身会出现"身体朝前、人却往旁边平移"的拧巴状态，像螃蟹横行 |
| 不做左右**侧闪动画** | 明确不做额外的第三/第四段动画 | 侧闪要求玩家先判断"往左躲还是往右躲"，判断成本高。而"按 A 就朝左边前闪"已经覆盖了九成的侧向拉开需求，却**不用多一套动画** —— 侧移的位移需求由"前闪 + 转身"一并解决 |
| 位移与时长 | **前闪 0.375s ≈ 4.0m**（`dodge_forward_speed` 14.0）；**后闪 0.458s ≈ 3.0m**（`dodge_back_speed` 8.7） | 两者手感诉求相反：前闪要"快、远、压上去"，后闪要"干脆、留出反应距离"。用同一组数值的话，要么前闪不够远、要么后撤太飘。★ **数值反推时注意暗亏**：位移 = speed × 0.725 × 时长（见下一条），只看 speed 数字会高估近三成 —— 旧值 6.6 / 4.8 实际只能挪 1.8 / 1.6 m，试玩反馈"太短"就是这么来的 |
| 速度曲线 | 起步满速 → 末段衰减到 45%（**时间均值 0.725**） | 纯匀速的闪避像"贴地滑行"，末段收一下才有"刹住"的重量感。⚠️ 这条曲线是"距离算错"的根源：写在代码里的是**峰值速度**，实际平均只有它的 0.725 倍 |
| 无敌帧 | **整段闪避全程无敌** | 无敌帧比动画短的话会出现"看着已经闪出去了、血却掉了"这种最劝退的反馈；闪避本身已经有硬代价（时长固定、不能取消、收招期间挨打），不需要再抠无敌帧 |
| 完美闪避判据 | **敌人挥击判定盒开启时，正好命中你的闪避无敌帧** | 与完美格挡**同源**（都从 `take_damage` 这同一个入口进来）：敌人侧完全不需要知道"玩家在闪避"，不用新增任何判定窗、也不用为闪避单独调敌人参数 |
| 完美闪避回报 | 三样一起给：**青蓝闪光 + 角色残影 + 子弹时间** | 缺一样玩家都会"不知道自己刚刚做对了什么"：闪光 = 瞬时确认，残影 = 空间残留（把"我从哪闪开的"画出来，也是唯一的帅气来源），子弹时间 = 时间层面的奖励 |
| 子弹时间范围 | **全局 `Engine.time_scale` 降到 0.45**，保持 **0.25 真实秒**，再 **0.25s 平滑回升**（合计 0.5s） | ★ 特意**连玩家一起慢**：只慢敌人的话这就不是演出而是"免费的输出窗口"，强度立刻失控。全局减速是纯粹的**确认/表演**奖励 —— 奖励你**看清战场**，而不是**多砍两刀**。★ 时长从 0.6s 收到 0.25s：慢动作拖久了会变成"停下来喘气"，把战斗节奏切断 |
| 一次闪避只给一次完美判定 | 一次闪避内只认第一下 | 与完美格挡同理：否则站在多段攻击（或怪堆）里按住 Shift 就能反复白嫖慢动作 |
| 完美闪避**不动敌人** | 闪避不产生任何敌人侧效果 | 闪避是"我躲开了"，格挡是"我顶回去了"。前者不该反过来控制敌人，否则两个机制的定位就糊在一起了 |
| **后闪**不改朝向 | 单按 Shift 后跳**不转身** | 后撤转身会让"看着敌人后退"变成"背对敌人跑"；与受击同一条全局规则（受击也只被击退、不回头） |
| **前闪**可以转身，锁定时也一样 | 按方向键会临时把朝向借走，**闪避结束后自动转回敌人** | 用户明确要求：位移意图优先。技术上安全地点是 —— `_face_lock_target()` 只在 MOVE / BLOCK 里被调用，DODGE 期间没人把朝向拉回去，**锁定状态本身不受影响**（也不该解除，白点一直在）。`lock_toggle_probe` 的 T10 钉住这条 |
| 与格挡的关系 | 各自独立、互不干扰 | 都占用"被命中那一刻"这一个时间点，但一个要求**按住右键迎击**、一个要求**按下 Shift 脱离**，是两种对立的操作，不存在同时成立 |

时序（`player.gd` 的 `DODGE` 状态 + `_trigger_perfect_dodge()`）：

```
方向键 + Shift ──▶ 身体**先转向**那个方向 ──▶ 前闪 DODGE（0.375s / ≈4.0m，全程无敌）
       单按 Shift ──▶ 后闪 DODGE（0.458s / ≈3.0m，沿身体正后方，**不转身**）
                             │
   这段无敌帧里被敌人挥击判定盒扫到 ──▶ 完美闪避：
                             │              · 0 伤害（这一下被闪掉了）
                             │              · 青蓝亮球闪光（冷色，与完美格挡的金色区分）
                             │              · 身后拖出 3 道角色残影，各自淡出后自毁
                             │              · 子弹时间：全局 0.45 倍速 0.25s → 0.25s 回升
                             │              · HUD 青蓝闪屏
         无敌帧过后才被扫到 ──▶ 普通挨打：吃满伤害 + HURT 硬直 + 击退
            全程没被扫到    ──▶ 平静收招回 MOVE（锁定时由 `_face_lock_target` 把朝向转回敌人）
                             │
               一次闪避内只认第一下（否则怪堆里按住 Shift 就能刷慢动作）
```

全部数值都在 `player.gd` 顶部 `@export`（`dodge_forward_time/speed`、`dodge_back_time/speed`、
`bullet_time_scale/duration/fade`、`ghost_count/life/color`），编辑器里可实时调。
⚠️ 改 `dodge_*_time` 时必须同步换算 `dodge_*_speed` —— 距离 = speed × **0.725** × 时长（速度曲线的均值），
三者只改其一会让"实际挪多远"悄悄跑偏 —— 2026-09-20 用户反馈"闪避距离太小"，查出来就是这句乘法没算清楚。

### 三段连击（已实现，设计定稿）

设计目标：让"一直按左键"变成一件**有节奏、有承诺、有回报**的事 ——
单段攻击只能表达"我砍了一刀"，连击才能表达"我压着你在打"。

| 决策项 | 结论 | 理由 |
|---|---|---|
| 段数 | **固定 3 段**（`Slash` → `Slash2` → `Slash3`），各有专属动画 | 3 段是"读得出轻重"的最小数量：第 1 段起手、第 2 段顺着力甩出去、第 3 段收尾重击。再多就要开始记账（玩家得背板才能记住打到第几段） |
| 触发方式 | **同一把左键**：`ATTACK` 期间再按 = 连击意图（**不占用新键位**） | 动作游戏惯例；也为后面"轻重攻击分键"留了余地（真正的重击才需要独立键） |
| 接续条件 | **后摇取消点**（`combo_cancel_1/2`）之后兑现 → 掐掉剩余收招、直接接下一段 | 「后摇取消」是连击流畅感的来源：判定窗刚过就能顺势甩出下一刀，而不是干等收招演完。取消点比判定窗末端再晚一点点（"打到就能接"而不是"抬剑就能接"） |
| 取消点之前按 | 记进**输入缓冲**（`combo_buffer_time` 0.30s），到点自动兑现 | 没有缓冲就必须掐帧去按，"早了无效、晚了断链"——手感立刻变硬。缓冲让"我打算接着打"这个意图被听见 |
| 缓冲过期 | 超过 0.30s 就作废 | 否则"很久以前随手按的一下"会在零点几秒后**替玩家接一段**，玩家完全无法理解这一刀从哪来 |
| ★ **第 3 段不可取消** | 没有取消点，必须站着把 0.583s 的长后摇演完 | **这就是连击的代价**。若三段都能取消，连击就成了"只有收益没有风险"，玩家会无脑一直按 —— 收招期间挨打正是对手的翻盘窗口 |
| 伤害递增 | **25 / 30 / 40**（合计 **95**） | 递增让收尾有"重击"的分量。合计 95 **故意不到 100**：一次完整连击打不死任何敌人，最后仍要补一刀 —— 与既有节奏一致（处决 75 之后也是留恰好一刀的量）。同时第 1 段伤害仍是 25（= 老版 `attack_damage`），老断言与"4 刀一杀"的心算不变 |
| 时长配比 | **0.500 / 0.417 / 0.583**（长—短—长） | 第 2 段是"顺着力甩出去"的横斩，本来就该更短更干脆；第 3 段最长 = 收尾的"重量"。三段的节奏感靠这个配比，不是靠数值 |
| 每一段都重新吸附朝向 | 接段时重跑 `_aim_direction()` + `_face_instant()` | 敌人被前一段**打退了**，第 2/3 段必须跟着转，否则会出现"对着空气连挥三刀"——这正是软锁定要解决的问题 |
| 冷却分两档 | 普通收招 `attack_cd` 0.42；**第 3 段**收尾 `combo_finish_cd` 0.62 | 收尾重击的"重量"也体现在冷却上：多站一会儿，让"打完整套"这件事有代价而非纯收益 |

**命中反馈三件套**（每次命中同时给，缺一样都会"感觉没打到"）：

| 反馈 | 参数 | 说明 |
|---|---|---|
| **顿帧 hitstop** | `hitstop_normal` 0.055s / `hitstop_finisher` 0.11s，期间 `time_scale` 压到 **0.05** | 把全局时间几乎冻住，让"这一刀吃进去了"有物理上的重量感。收尾重击给双倍时长 |
| **镜头震动** | `shake_normal` 0.035 / `shake_finisher` 0.085，`shake_time` 0.16s | 施加在**子节点 Camera3D 的局部偏移**上（`h_offset/v_offset` + 轻微滚转）。先去动 `global_position` 会被下一帧的 `look_at` 覆盖，跟平滑跟随打架会变成抖屏 |
| **音效** | `swing_light` / `swing_heavy` / `hit_impact`（`AudioStreamPlayer3D`） | 起手播破空声（第 3 段用更沉的重挥），命中播打击声。用 3D 播放器 → 有距离衰减与方位感（听声辨位的基础） |

★ **顿帧与子弹时间是两个独立因子，最终取更慢者**：
`Engine.time_scale = min(_bt_factor, _hs_factor)`。
两者都会压慢全局时间，但用途/时长/深度完全不同（子弹时间是奖励玩家的表演时间，顿帧是打击感）。
若共用一个变量，后写的一方会盖掉对方，且先前那个补间到点还会把对方的减速一起拉回 1.0
（画面会突然"抽一下"）。拆成两因子后：完美闪避里打中敌人也表现正常，互不干扰。

**音效是程序化合成的**（`tools/gen_sfx.py`，纯 Python、无第三方依赖）：
挥砍 = 带通噪声 + 时变共振峰（"嗖"的本质就是噪声的共振峰在移动）+ 快起慢落包络；
命中 = 瞬态噪声（"啪"）+ 85→46Hz 扫频正弦（"砰"）+ 中频填充。
每个文件 < 17 KB、可复现、可微调，且按同一套参数就能给敌人侧生成挥击/受击音。

时序（`player.gd` 的 `ATTACK` 状态 + `_start_combo_step()`）：

```
左键 ──▶ ATTACK 第1段 Slash(0.500s)  判定窗 0.17~0.28  伤害 25
            │
   取消点 0.30s 之前再按 ──▶ 记进输入缓冲(0.30s 寿命)
            │
   到 0.30s（缓冲还活着）──▶ 掐掉剩余收招 ──▶ 第2段 Slash2(0.417s) 判定窗 0.12~0.30 伤害 30
            │                                        │
            │                        取消点 0.28s 之前再按 ──▶ 同上，缓冲兑现
            │                                        ▼
            │                          第3段 Slash3(0.583s) 判定窗 0.16~0.42 伤害 40
            │                                        │
            │                          ★ 没有取消点：中途按左键**连缓冲都不记**
            │                                        │
            └── 没人接 ──▶ 演完整段回 MOVE + 冷却 --- 演完回 MOVE + combo_finish_cd 0.62s
                                    （普通段用 attack_cd 0.42s）
每次命中同时触发 ──▶ 顿帧（0.055/0.11s，time_scale→0.05）+ 镜头震动 + 打击音效
```

参数全在 `player.gd` 顶部 `@export`。**第 1 段的参数沿用老的 `attack_*` 四个标量**（不并进数组）：
自动化测试与调参注释都直接读 `player.attack_total` 这些名字，挪进数组等于凭空制造一次
"改参数就得改测试"的重构；第 2/3 段另起 `combo2_*` / `combo3_*`。

### 格挡机制（已实现，设计定稿）

设计目标：让"按住"和"按下"两种操作都有意义 —— 按住是**稳住**，按下时机准是**反打**。

| 决策项 | 结论 | 理由 |
|---|---|---|
| 机制形态 | **按住减伤 + 时机判定 两者结合**（而非二选一） | 只做减伤 → 变成无脑长按；只做弹反 → 面对连续攻击没有容错 |
| 按键 | **鼠标右键**（左=攻击 / Shift=闪避 / 空格=跳跃） | 右手拇指区，与攻击键同手，符合动作游戏惯例 |
| 普通格挡 | 减伤 **70%**（至少吃 1 点）、**不硬直、不击退**，移速 ×0.3 | "至少 1 点"是关键：否则高减伤等于无敌，玩家会一直按住不放 |
| 完美格挡 | 按下的**前 0.45s** 内挡下 → **0 伤害** + 攻击者 **0.8s** 硬直 + **黄光特效** + 敌人失衡值 +N% | 0.8s 是普通受击(0.4s)的两倍，足够打出一刀（`attack_total` 0.5s）→ 明确的"反打回报" |
| 完美判定窗口 | **0.45s**（沿革 0.15 → 0.22 → 0.45） | 窗口一路放宽是安全的：**一次按住只给一次完美判定**把上限兜住了，不会退化成"按住右键就无敌"。0.45s 让"看到棒子举起就按右键"这个直觉动作稳定吃到 |
| 完美判定次数 | 一次**按住**只给一次 | 否则"长按不放"每次挨打都白嫖一次弹反，节奏博弈消失 |
| 方向限制 | 只有来自**正面 120° 锥形**内的攻击能被挡住 | 不然可以背对敌人无脑按住；也让"绕背"成为敌人的有效手段 |
| 格挡中能否行动 | 不能攻击 / 闪避 / 跳跃；可以小碎步挪 | 有防御就不能有输出与位移，保持动作游戏的承诺感 |
| 破防后 | 硬直结束若仍按住 → **自动重新举剑**，但不重置完美窗口 | "按住=持续格挡"是设计承诺；若必须松手再按会很别扭。但不白送窗口，避免"按住 → 被打 → 自动重举 → 白拿弹反"的套路 |
| 敌人侧反馈 | 新增 `deflect()`：**不掉血**、长硬直、推力 ×1.4、闪更亮 | 与"被打伤"区分开：弹反是"被挡开"，不该同时掉血，否则奖励感混乱 |

时序（`player.gd` 的 `BLOCK` 状态 + `_block_play()`）：

```
按下右键 ──▶ BLOCK：Block(起手 0.25s) ──▶ BlockHold(循环举剑)
                 │
      前 0.45s 内被攻击 ──▶ 完美格挡：0 伤害 + 黄光 + 敌人 STAGGER 0.8s + 失衡值 +N%
      窗口过后被攻击   ──▶ 普通格挡：扣 30% 伤害 + 插播 BlockImpact 顿挫
      背后被攻击       ──▶ 挡不住：吃满伤害 + HURT 硬直
松开右键 ──▶ 收招回 MOVE
```

待试玩确认的数值：**0.45s 窗口是否偏松**（新玩家友好度 vs 挑战性）、70% 减伤是否让"格挡"过于安全、
0.8s 硬直是否足够打出一刀。三个值都在 `player.gd` 顶部 `@export`，编辑器里可实时调。

### 失衡条与处决（已实现，设计定稿）

设计目标：给"完美格挡"一个**跨回合的积累目标** —— 单次弹反只换来 0.8s 硬直，
连续弹中几次则换来一次**高额处决**，让"敢于迎击"比"绕圈磨血"更划算。

| 决策项 | 结论 | 理由 |
|---|---|---|
| 形态 | **积累条**（只涨不落，默认无自然回落） | 与血条（消耗条）反义。只涨才能形成"攒够 N 次必然处决"的**确定节奏**，玩家能规划 |
| 加值来源 | **只有完美格挡**会加 | 它本质上是"弹反奖励的进度条"。若普通攻击也加，就退化成"打得多自然失衡"，格挡的博弈价值被稀释 |
| 数值规则 | 每次加**上限的百分比**，各类敌人不同 | 调参概念可读：`percent = 100 ÷ 期望弹反次数`。守卫 **34%（3 次）**；小怪 50（2 次）/ 重甲 25（4 次）/ Boss 20（5 次） |
| 差异化实现位置 | 敌人自己的 `@export parry_poise_percent` | 玩家侧完全不关心"这只怪加多少"，换皮/换难度只改敌人这一个字段 |
| 涨满后 | 进入 **BROKEN（失衡）**：不能出手、命中盒关闭、站不稳打晃，持续 `break_time`（3.0s） | 一个明确的"惩罚窗口"：敌人交出行动权，玩家收获进攻权 |
| 处决触发 | 走近失衡敌人 **按左键**（复用攻击键，`execute_range` 2.6m 内） | 不为处决多记一个键；失衡窗口稍纵即逝，优先响应处决更符合直觉。没失衡敌人时左键仍是普通挥剑 |
| 处决演出 | 专属动画 **`Execute`：举剑 → 前刺（命中帧）→ 上划 → 收招**，整段 1.0s | 三段各有清晰剪影，读起来是"处决"而不是"又砍一刀"。（在此之前复用 `Slash` 慢放 0.67 倍速） |
| 处决伤害 | **大量，但刻意不致命**：`execute_damage` **75**（守卫满血 100 → 挨完剩 25） | 若一击必杀，最优解就退化成"格挡→秒杀→格挡→秒杀"，普通挥砍（25/刀）被架空；而且处决自带全程无敌，能秒杀=无敌+秒杀，强度失控。留 25 = **正好一刀 `attack_damage` 的量** → **处决负责重创、补刀负责收人头**，两段都有演出 |
| 处决的代价 | 锁方向自动贴近 → **全程无敌** → 判定时刻结算伤害 → 金爆闪 | 无敌换来"处决值得用"；真正的代价是整段 **1.0s 比普通挥砍的 0.5s 长一倍**，怪堆里无脑处决会在收招时挨打 |
| 失衡被"消耗" | 演出结束时调 `end_break_after_execution()` **主动收掉失衡**，敌人爬起来 | 伤害改成非致命后敌人会活着留在 BROKEN 里；不收掉的话玩家能原地连按左键**无限连处决**（还全程无敌），处决从"一次性的高光"退化成"刷伤害的循环" |
| 抗性差异 | 敌人侧 `execute_damage_scale` 乘算 | 大块头理应更抗处决：精英/Boss 调低倍率即可让它需要被处决两次 |
| 演出不被中断 | 处决时调用 `poise.refresh_break()` 把失衡倒计时**顶回满** | 否则处决演到一半敌人自己站起来，动作被打断。（"爬起来"只发生在玩家收招之后，见上一行） |
| 失衡窗口不被误取消 | `deflect()` 在已 BROKEN 时**保持 BROKEN**，只给击退+闪光，不再加值 | 玩家在失衡期"多弹一下"不该把处决窗口消掉（否则表现为"处决突然没反应"） |
| 失衡结束 | 倒计时归零 → 自动恢复 CHASE，失衡值清空重攒（`break_keep_ratio=0`） | 取 0 让节奏确定；取 0.5 会让连续处决更容易，是可调的难度旋钮 |
| 组件化 | 独立 `Poise` 组件（`scripts/components/poise.gd`），与 `Health` 平级挂在战斗单位下 | 和血量一样"谁都能挂"：以后玩家/精英/Boss 都能有自己的失衡条，逻辑零改动 |

时序（`enemy.gd` 的 `BROKEN` 状态 + `player.gd` 的 `EXECUTE` 状态）：

```
完美格挡 ──▶ 敌人 STAGGER 0.8s + poise.percent(34%) ──3 次──▶ poise 满
                                                                    │
                                                                    ▼
                                          敌人 BROKEN（3.0s，不能出手、命中盒关闭）
                                                                    │
                            玩家在 2.6m 内按左键 ──▶ EXECUTE：无敌 + 自动贴近
                                                              │
                                   Execute 动画第 9 帧(前刺) ──▶ enemy.execute(75) → 金爆闪
                                                              │     · 敌人**打不死**（剩 25 血），保持 BROKEN 演完
                                   处决刷新失衡倒计时（演出不被打断）→ 演完回 MOVE
                                                              │
                                   收招瞬间 ──▶ end_break_after_execution()：敌人爬起来（失衡被消耗）
                                                              │
                                   玩家补一刀(25) ──▶ 击杀
                                                                    │
                    3.0s 内没被处决 ──▶ 自动恢复 CHASE，失衡值清空
```

- **武器与角色分离**：角色只带挂点骨骼 `weapon.R`，武器在 Godot 里用 `BoneAttachment3D` 附加。

- **武器对齐（实测修正）**：武器资产的原点 = 握把中心、**刀身沿局部 -Z**。
  挂点骨骼 `weapon.R` 的静止基实测为 +Y≈模型前方(-Z)、+Z≈模型上方、+X≈模型右侧——
  即"沿 +Y 指向前方"的持械轴。因此对齐规则是：**握柄停在骨骼原点(拳心)、刀身沿骨骼 +Y 指向身前**，
  代码里就是常量 `WEAPON_ALIGN_LOCAL`（绕骨骼 X 轴 +90°）。
  两个踩过的坑：① 单位变换直挂会让刀身朝**下**（整把剑掉到 y≈-0.4）；
  ② 照抄"武器分离前"旧模型的竖直位置会让刀身**嵌在手臂里**（旧模型里剑就是贴着手臂竖直朝上的）。
  实测结果：握柄偏差 **0.000 m**、刀身与身前夹角 **8°**；回归方式：
  `tools/check_weapon.tscn` + 自动测试的 6 项武器断言。
